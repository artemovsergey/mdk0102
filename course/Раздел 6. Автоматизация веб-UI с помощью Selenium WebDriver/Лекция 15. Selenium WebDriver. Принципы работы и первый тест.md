### **Подробное рассмотрение каждого пункта плана**

#### **1. Что такое Selenium и Selenium WebDriver**

**Подробное объяснение:**

**Selenium** — набор инструментов для автоматизации браузеров. Основные возможности:

* автоматизация действий пользователя в реальном браузере (Chrome, Firefox, Edge);
* поддержка разных языков: C#, Java, Python, JavaScript;
* применение для функционального (end-to-end) тестирования веб-приложений.

**Selenium WebDriver** — библиотека, которая позволяет управлять браузером из кода: открывать страницы, находить элементы, кликать, вводить текст, получать значения.

| Инструмент | Назначение |
|-----------|------------|
| Selenium WebDriver | Управление браузером из кода (наш основной инструмент) |
| Selenium IDE | Запись действий в браузере без программирования |
| Selenium Grid | Запуск тестов на нескольких машинах/браузерах параллельно |

**Важно:** UI-тест проходит «сквозь» весь стек приложения (браузер → фронтенд → API → БД), поэтому такие тесты самые медленные и самые хрупкие. Их пишут меньше, чем юнит- и интеграционных, но именно они проверяют систему глазами пользователя.

#### **2. Как работает WebDriver: браузерные драйверы и Selenium Manager**

**Подробное объяснение:**

WebDriver работает по принципу **клиент-сервер**:

1. код теста (клиент) отправляет команду по HTTP;
2. **драйвер браузера** (ChromeDriver, GeckoDriver, EdgeDriver) транслирует её конкретному браузеру;
3. браузер выполняет действие (открывает страницу, кликает, вводит текст);
4. результат возвращается в код теста.

```
[Тест на C#] --> [WebDriver API] --> [Драйвер браузера] --> [Браузер]
```

| Браузер | Драйвер | `IWebDriver`-класс |
|---------|---------|---------------------|
| Chrome | ChromeDriver | `ChromeDriver` |
| Firefox | GeckoDriver | `FirefoxDriver` |
| Edge | EdgeDriver | `EdgeDriver` |

Раньше драйвер приходилось скачивать и обновлять вручную — после обновления браузера тесты «внезапно» переставали запускаться. В **Selenium 4.6+** эту работу выполняет **Selenium Manager**: при первом запуске он сам определяет версию установленного браузера, скачивает подходящий драйвер и кэширует его.

**Что это значит на практике:**

* отдельные NuGet-пакеты с драйверами (`Selenium.WebDriver.ChromeDriver`, `Selenium.WebDriver.GeckoDriver`) больше **не нужны** — они устарели;
* браузер (например, Chrome) должен быть установлен в системе — его Selenium Manager не скачивает;
* при первом запуске нужен доступ в интернет (дальше драйвер берётся из кэша).

#### **3. Установка Selenium в проект .NET**

**Подробное объяснение:**

Проект создаётся как обычный тестовый проект xUnit (лекция 9), затем добавляются два пакета:

```bash
dotnet new xunit -n UIAutomationTests
cd UIAutomationTests
dotnet add package Selenium.WebDriver --version 4.49.0
dotnet add package Selenium.Support --version 4.49.0
```

| Пакет | Зачем нужен |
|-------|-------------|
| `Selenium.WebDriver` | Классы `IWebDriver`, `ChromeDriver`, `By`, навигация |
| `Selenium.Support` | `WebDriverWait`, `SelectElement`, `PageFactory` (вспомогательные API) |

В `UIAutomationTests.csproj` появятся соответствующие `PackageReference`:

```xml
<ItemGroup>
  <PackageReference Include="Microsoft.NET.Test.Sdk" Version="17.14.1" />
  <PackageReference Include="Selenium.Support" Version="4.49.0" />
  <PackageReference Include="Selenium.WebDriver" Version="4.49.0" />
  <PackageReference Include="xunit" Version="2.9.3" />
  <PackageReference Include="xunit.runner.visualstudio" Version="3.1.4" />
</ItemGroup>
```

> Драйвер браузера отдельным пакетом не устанавливается — его скачает Selenium Manager при первом запуске теста.

#### **4. Первый UI-тест**

**Подробное объяснение:**

Откройте страницу и проверьте её содержимое:

```csharp
using OpenQA.Selenium;
using OpenQA.Selenium.Chrome;
using Xunit;

public class FirstUiTest
{
    [Fact]
    public void HomePage_HasExpectedTitle()
    {
        // 1. Arrange: создаём браузер
        using IWebDriver driver = new ChromeDriver();

        // 2. Act: открываем страницу
        driver.Navigate().GoToUrl("https://example.com");

        // 3. Assert: проверяем результат
        Assert.Contains("Example Domain", driver.Title);
    }
}
```

Разбор теста:

* `using IWebDriver driver = new ChromeDriver();` — при первом выполнении Selenium Manager скачает драйвер; конструкция `using` гарантирует, что браузер будет закрыт (`Quit()`) даже при падении теста;
* `driver.Navigate().GoToUrl(...)` — переход по адресу;
* `driver.Title` — заголовок вкладки; `Assert.Contains` — проверка xUnit.

Если тестов несколько, браузер удобнее создавать в конструкторе тестового класса, а закрывать — в `Dispose()` (жизненный цикл xUnit — лекция 12):

```csharp
public class HomePageTests : IDisposable
{
    private readonly IWebDriver _driver;

    public HomePageTests()
    {
        _driver = new ChromeDriver();
        _driver.Manage().Window.Maximize();
    }

    [Fact]
    public void HomePage_IsAvailable()
    {
        _driver.Navigate().GoToUrl("https://example.com");
        Assert.NotNull(_driver.Title);
    }

    public void Dispose() => _driver.Quit();
}
```

#### **5. Основные команды WebDriver**

**Подробное объяснение:**

**Навигация и закрытие:**

```csharp
IWebDriver driver = new ChromeDriver();
driver.Navigate().GoToUrl("https://example.com"); // открыть URL
driver.Navigate().Back();                          // назад
driver.Navigate().Refresh();                       // обновить
driver.Quit();                                     // закрыть браузер полностью
driver.Close();                                    // закрыть текущую вкладку
```

**Поиск элементов:**

```csharp
IWebElement field = driver.FindElement(By.Id("username"));
IWebElement button = driver.FindElement(By.XPath("//button[text()='Войти']"));
```

| Локатор | Пример | Когда применять |
|---------|--------|-----------------|
| `By.Id` | `By.Id("login")` | Самый надёжный — уникальный id |
| `By.Name` | `By.Name("email")` | Атрибут name |
| `By.ClassName` | `By.ClassName("btn")` | CSS-класс (может быть не уникален) |
| `By.CssSelector` | `By.CssSelector("#form .btn")` | Сложные составные селекторы |
| `By.XPath` | `By.XPath("//a[@href='/login']")` | По тексту и структуре DOM |

Подробно локаторы разбираются в лекции 16.

**Взаимодействие с элементами:**

```csharp
element.SendKeys("Тест");   // ввод текста
element.Clear();            // очистка поля
button.Click();             // клик
string text = element.Text; // видимый текст элемента
bool visible = element.Displayed; // видимость
```

**Ожидания (кратко, подробно — лекция 18):**

```csharp
using OpenQA.Selenium.Support.UI;

var wait = new WebDriverWait(driver, TimeSpan.FromSeconds(10));
IWebElement element = wait.Until(d => d.FindElement(By.Id("username")));
```

#### **6. Запуск тестов и типичные проблемы**

**Подробное объяснение:**

Запуск — как обычных тестов xUnit:

```bash
dotnet test
```

Или через панель **Testing** в VS Code (лекция 9). Первый запуск может быть дольше: Selenium Manager скачивает драйвер.

| Проблема | Причина | Решение |
|----------|---------|---------|
| `SessionNotCreatedException` | Версия браузера несовместима с драйвером | Обновить Selenium Manager (в составе пакета Selenium.WebDriver), обновить браузер |
| Тест не видит элемент | Страница ещё не загрузилась | Использовать ожидания (лекция 18) |
| Браузер открывается, но тест падает | Неверный локатор | Проверить локатор в DevTools (F12) |
| Первый запуск «зависает» | Скачивается драйвер, нет интернета/прокси | Дождаться загрузки или настроить прокси |

### **Резюме**

1. Selenium WebDriver — библиотека для управления браузером из кода; тесты проходят весь стек приложения.
2. WebDriver работает по схеме «тест → драйвер → браузер»; драйвер транслирует команды конкретному браузеру.
3. Начиная с Selenium 4.6 драйверы скачивает Selenium Manager — отдельные NuGet-пакеты драйверов устарели и не нужны.
4. В .NET подключаются два пакета: `Selenium.WebDriver` 4.49.0 и `Selenium.Support` 4.49.0.
5. Первый тест: создать драйвер, открыть страницу, найти элемент, проверить результат ассертом xUnit, закрыть браузер.
6. Жизненный цикл браузера строится по правилам xUnit: конструктор — создание, `Dispose()` — закрытие.
7. Основные действия: навигация, поиск элементов (`By.*`), ввод/клик/текст, ожидания.
