# Практическая работа 31. Первый workflow GitHub Actions для юнит-тестов

### **Тема**

Создание первого workflow GitHub Actions: автоматический запуск юнит-тестов при push и pull request, публикация TRX-отчёта как артефакта.

### **Цель**

- Понять структуру workflow-файла GitHub Actions (name, on, jobs, steps).
- Научиться запускать сборку и тесты проекта в облачном runner.
- Настроить публикацию TRX-отчёта артефактом.
- Научиться читать логи упавших проверок в интерфейсе GitHub.

### **Теоретическая часть**

**GitHub Actions** — встроенная система CI/CD в GitHub. Для неё не нужен отдельный сервер: workflow-файлы лежат в репозитории в каталоге `.github/workflows/`, а запускаются они на виртуальных машинах (runners), которые GitHub предоставляет бесплатно для публичных репозиториев.

Файл workflow — это YAML-документ. Минимальная структура:

```yaml
name: Unit tests        # имя workflow (отображается во вкладке Actions)

on:                     # события-триггеры
  push:
    branches: [main]
  pull_request:

jobs:                   # набор задач
  test:                 # идентификатор задачи
    runs-on: ubuntu-latest   # образ runner

    steps:              # шаги выполняются последовательно
      - name: Клонирование репозитория
        uses: actions/checkout@v7    # готовое действие с Marketplace
      - name: Сборка
        run: dotnet build           # команда оболочки
```

Ключевые понятия:

| Понятие | Что означает |
|---------|--------------|
| `on` | События, при которых запускается workflow (`push`, `pull_request`, `schedule`, `workflow_dispatch` и др.) |
| `job` | Группа шагов, выполняемая на одном runner |
| `runs-on` | Образ виртуальной машины: `ubuntu-latest`, `windows-latest`, `macos-latest` |
| `step` | Один шаг: команда (`run`) или готовое действие (`uses`) |
| `uses` | Подключение готового действия, например `actions/checkout` |
| `with` | Параметры действия (версия .NET, имя артефакта и т. п.) |
| runner | Виртуальная машина, на которой выполняется job |

**Стандартные действия**, которые понадобятся почти в любом .NET-пайплайне:

- `actions/checkout` — клонирует репозиторий на runner (без него там пусто);
- `actions/setup-dotnet` — устанавливает нужную версию .NET SDK;
- `actions/upload-artifact` — сохраняет файлы (отчёты, скриншоты) как артефакты, скачиваемые со страницы запуска.

**Артефакты.** Артефакт — файл или каталог, прикреплённый к результату запуска. Отчёт `results.trx`, созданный при падении тестов, сохраняется для разбора: скачав артефакт, можно открыть TRX и увидеть сообщение об ошибке. Шаг публикации ставят с условием `if: always()`, иначе при упавших тестах до публикации дело не дойдёт.

### **Ход работы**

1.  Откройте проект `LibraryApp.sln` из Практической работы 30 и убедитесь, что тесты локально проходят:

    ```bash
    dotnet test
    ```

2.  В корне репозитория создайте каталог `.github/workflows` и файл `unit-tests.yml`:

    ```bash
    mkdir -p .github/workflows
    code .github/workflows/unit-tests.yml
    ```

3.  Внесите в файл содержимое из практического примера (адаптируйте путь к тестовому проекту, если он отличается).

4.  Закоммитьте и запушьте в GitHub:

    ```bash
    git add .github/workflows/unit-tests.yml
    git commit -m "ci: workflow для запуска юнит-тестов"
    git push
    ```

5.  Откройте страницу репозитория на GitHub → вкладка **Actions**. Убедитесь, что запустился workflow «Unit tests».

6.  Пройдите по запуску: кликните по имени workflow, затем по job `test`. Разверните шаги и найдите:
    - вывод шага «Установка .NET SDK» (какая версия установлена);
    - вывод шага «Запуск юнит-тестов» (итоговая строка о числе тестов).

7.  Прокрутите страницу запуска до раздела **Artifacts**: там должен лежать артефакт `test-results`. Скачайте его, распакуйте и откройте `results.trx` — найдите в нём свои тесты.

8.  Проверьте поведение при падении: временно сломайте один тест (неверное ожидаемое значение), сделайте commit и push. Дождитесь, когда запуск станет красным. Изучите:
    - сообщение об ошибке на странице запуска;
    - строку `outcome="Failed"` и секцию `<ErrorInfo>` в TRX из артефакта.
      Верните тест в рабочее состояние и запушьте исправление.

9.  Сделайте скриншоты: вкладка Actions со зелёным запуском, страница job с шагами, раздел Artifacts. Сохраните их в папку `images`.

10. Оформите `README.md` (добавьте бейдж из практики 33 или раздел о CI) и зафиксируйте изменения.

### **Практический пример**

**Файл `.github/workflows/unit-tests.yml`:**

```yaml
name: Unit tests

on:
  push:
    branches: [main]
  pull_request:

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - name: Клонирование репозитория
        uses: actions/checkout@v7

      - name: Установка .NET SDK
        uses: actions/setup-dotnet@v6
        with:
          dotnet-version: '10.0.x'

      - name: Восстановление зависимостей
        run: dotnet restore

      - name: Сборка
        run: dotnet build --no-restore --configuration Release

      - name: Запуск юнит-тестов
        run: >
          dotnet test LibraryApp.Tests/LibraryApp.Tests.csproj
          --no-build --configuration Release
          --logger "trx;LogFileName=results.trx"
          --results-directory TestResults

      - name: Публикация отчёта о тестах
        if: always()
        uses: actions/upload-artifact@v7
        with:
          name: test-results
          path: '**/TestResults/*.trx'
```

**Пояснения к ключевым местам:**

- `dotnet-version: '10.0.x'` — установить последнюю версию .NET 10 (кавычки обязательны: `10.0.x` не должен читаться как число);
- `dotnet build --no-restore` — сборка после отдельного восстановления пакетов: это быстрее и понятнее в логах;
- `--no-build` в `dotnet test` — тесты запускаются на уже собранной конфигурации Release;
- `if: always()` — артефакт публикуется даже при провале предыдущих шагов. Без этого условия при упавших тестах отчёт теряется;
- `path: '**/TestResults/*.trx'` — маска поиска файлов отчёта от корня репозитория.

**Как выглядит падение в логах.** Шаг «Запуск юнит-тестов» завершается с ошибкой и на странице видно:

```
Failed AddBookAsync_DuplicateIsbn_ThrowsInvalidOperationException [< 1 ms]
  Error Message:
   xUnit.net Assert.Throws() Failure: No exception was thrown
```

### **Критерии оценки**

*   **5 (Отлично):**
    *   Workflow создан в `.github/workflows`, запускается по push.
    *   На вкладке Actions виден успешный запуск; тесты выполняются на runner.
    *   TRX-артефакт публикуется и содержит результаты тестов.
    *   Продемонстрировано поведение при падении теста (артефакт сохраняется).
    *   Скриншоты в `images`, работа закоммичена и запушена.

*   **4 (Хорошо):**
    *   Workflow работает, артефакт публикуется, но случай падения не разобран.
    *   В YAML есть неточности (лишние кавычки, неоптимальные шаги), не мешающие работе.

*   **3 (Удовлетворительно):**
    *   Workflow создан, но падает из-за ошибок конфигурации (неверный путь к проекту, отсутствует checkout).
    *   Артефакт не публикуется.

*   **2 (Неудовлетворительно):**
    *   Workflow не создан или не запускается; тесты не проходят локально; работа не сдана.
