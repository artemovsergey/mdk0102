# Практическая работа 32. Интеграция API- и UI-тестов в pipeline

### **Тема**

Интеграция API- и UI-тестов в CI: параллельные job, запуск тестируемого API в фоне, ожидание готовности, headless-режим браузера и публикация скриншотов упавших тестов.

### **Цель**

- Научиться описывать в workflow несколько независимых job.
- Запускать тестируемый сервер (API) прямо на runner и дожидаться его готовности.
- Настроить headless-режим Chrome для UI-тестов в CI.
- Публиковать скриншоты упавших UI-тестов как артефакты.

### **Теоретическая часть**

**Несколько job в одном workflow.** Каждый job выполняется на отдельном чистом runner и не видит файлы другого job. Jobs по умолчанию запускаются параллельно — это ускоряет пайплайн: пока идут UI-тесты, API-тесты работают в другой виртуальной машине. Если один job должен ждать другого, указывают зависимость `needs`.

**Запуск API в фоне.** В CI нет «вечно работающего» окружения: сервер нужно поднять прямо в job. Процесс запускается в фоне (`&` в bash), затем pipeline ждёт, пока он начнёт отвечать. Надёжный приём — цикл с ограничением по времени:

```bash
for i in $(seq 1 30); do
  if curl -s http://localhost:5080/api/books > /dev/null; then
    exit 0
  fi
  sleep 1
done
exit 1
```

Идентификатор фонового процесса сохраняют в переменную окружения через файл `$GITHUB_ENV`, чтобы затем остановить сервер даже при упавших тестах (`if: always()`).

**Headless-режим.** На сервере нет графической оболочки, поэтому браузер запускается без окна — в headless-режиме. Для Chrome это флаги `--headless=new`, `--no-sandbox`, `--disable-dev-shm-usage`. Режим включается переменной окружения, которую workflow передаёт тестам (`HEADLESS: 'true'`), — локально тесты можно гонять с окном, в CI — без.

На GitHub-раннере `ubuntu-latest` браузер Chrome и chromedriver уже предустановлены, а Selenium Manager (Selenium 4.6+) находит их автоматически — ничего доустанавливать не нужно.

**Скриншоты упавших тестов.** В CI невозможно «посмотреть глазами» — поэтому UI-тест при падении сохраняет скриншот, а workflow публикует каталог со скриншотами артефактом с условием `if: failure()`. Скачав артефакт, видно, на каком экране произошёл сбой.

### **Ход работы**

1.  Откройте решение с проектами `LibraryApi` (из практики 28), `LibraryApp.ApiTests` и `LibraryApp.UiTests`.

2.  Убедитесь, что API-тесты читают адрес сервера из переменной окружения (а не из жёстко прописанного в коде адреса). Пример:

    ```csharp
    // LibraryApp.ApiTests/LibraryApiTests.cs
    private static string BaseUrl =>
        Environment.GetEnvironmentVariable("LIBRARY_API_URL") ?? "http://localhost:5080";
    ```

3.  В `LibraryApp.UiTests` создайте класс `DriverFactory` с поддержкой headless-режима (см. практический пример).

4.  В UI-тестах добавьте сохранение скриншота при падении в каталог `screenshots` (см. практический пример).

5.  Локально прогоните оба набора тестов:

    ```bash
    dotnet test LibraryApp.ApiTests
    dotnet test LibraryApp.UiTests
    ```

6.  Создайте файл `.github/workflows/api-ui-tests.yml` с содержимым из практического примера.

7.  Закоммитьте и запушьте:

    ```bash
    git add -A
    git commit -m "ci: API- и UI-тесты в pipeline"
    git push
    ```

8.  Во вкладке **Actions** убедитесь, что оба job (`api-tests` и `ui-tests`) запустились параллельно. Отметьте в логах:
    - шаг «Ожидание готовности API» — сколько секунд ждал сервер;
    - шаг «Запуск UI-тестов (headless Chrome)» — число тестов.

9.  Сломайте один UI-тест (измените ожидаемый заголовок страницы), запушьте. После красного запуска скачайте артефакты `ui-test-results` и `ui-screenshots`, откройте TRX и скриншот. Верните тест в рабочее состояние.

10. Сделайте скриншоты: параллельные job в Actions, раздел Artifacts со скриншотами. Сохраните в `images` и оформите README.

### **Практический пример**

**Файл `.github/workflows/api-ui-tests.yml`:**

```yaml
name: API and UI tests

on:
  push:
    branches: [main]
  pull_request:

jobs:
  api-tests:
    runs-on: ubuntu-latest

    steps:
      - name: Клонирование репозитория
        uses: actions/checkout@v7

      - name: Установка .NET SDK
        uses: actions/setup-dotnet@v6
        with:
          dotnet-version: '10.0.x'

      - name: Восстановление зависимостей
        run: dotnet restore

      - name: Запуск API в фоне
        run: |
          dotnet run --project LibraryApi/LibraryApi.csproj --urls http://localhost:5080 &
          echo "API_PID=$!" >> "$GITHUB_ENV"

      - name: Ожидание готовности API
        run: |
          for i in $(seq 1 30); do
            if curl -s http://localhost:5080/api/books > /dev/null; then
              echo "API готов"
              exit 0
            fi
            sleep 1
          done
          echo "API не запустился за 30 секунд" >&2
          exit 1

      - name: Запуск API-тестов
        run: >
          dotnet test LibraryApp.ApiTests/LibraryApp.ApiTests.csproj
          --logger "trx;LogFileName=api-results.trx"
          --results-directory TestResults
        env:
          LIBRARY_API_URL: http://localhost:5080

      - name: Остановка API
        if: always()
        run: kill "$API_PID" || true

      - name: Публикация отчёта об API-тестах
        if: always()
        uses: actions/upload-artifact@v7
        with:
          name: api-test-results
          path: '**/TestResults/*.trx'

  ui-tests:
    runs-on: ubuntu-latest

    steps:
      - name: Клонирование репозитория
        uses: actions/checkout@v7

      - name: Установка .NET SDK
        uses: actions/setup-dotnet@v6
        with:
          dotnet-version: '10.0.x'

      - name: Восстановление зависимостей
        run: dotnet restore

      - name: Запуск UI-тестов (headless Chrome)
        run: >
          dotnet test LibraryApp.UiTests/LibraryApp.UiTests.csproj
          --logger "trx;LogFileName=ui-results.trx"
          --results-directory TestResults
        env:
          HEADLESS: 'true'

      - name: Публикация отчёта о UI-тестах
        if: always()
        uses: actions/upload-artifact@v7
        with:
          name: ui-test-results
          path: '**/TestResults/*.trx'

      - name: Публикация скриншотов упавших тестов
        if: failure()
        uses: actions/upload-artifact@v7
        with:
          name: ui-screenshots
          path: '**/screenshots/**'
          if-no-files-found: ignore
```

**Фабрика драйвера с поддержкой headless (только фрагмент, полный код — в материалах раздела 6):**

```csharp
// LibraryApp.UiTests/DriverFactory.cs
using OpenQA.Selenium;
using OpenQA.Selenium.Chrome;

namespace LibraryApp.UiTests;

public static class DriverFactory
{
    public static IWebDriver Create()
    {
        var options = new ChromeOptions();

        // В CI (переменная HEADLESS=true) браузер запускается без окна
        if (Environment.GetEnvironmentVariable("HEADLESS") == "true")
        {
            options.AddArgument("--headless=new");
            options.AddArgument("--no-sandbox");
            options.AddArgument("--disable-dev-shm-usage");
            options.AddArgument("--window-size=1920,1080");
        }

        // Selenium Manager сам подберёт драйвер под установленный Chrome
        return new ChromeDriver(options);
    }
}
```

**Сохранение скриншота при падении UI-теста:**

```csharp
// LibraryApp.UiTests/TestBase.cs
using OpenQA.Selenium;

namespace LibraryApp.UiTests;

public abstract class TestBase : IDisposable
{
    protected readonly IWebDriver Driver;

    protected TestBase()
    {
        Driver = DriverFactory.Create();
    }

    protected void SaveScreenshot(string testName)
    {
        Directory.CreateDirectory("screenshots");
        var screenshot = ((ITakesScreenshot)Driver).GetScreenshot();
        screenshot.SaveAsFile(Path.Combine("screenshots", $"{testName}_{DateTime.UtcNow:HHmmss}.png"));
    }

    public void Dispose()
    {
        Driver.Quit();
        Driver.Dispose();
    }
}
```

**Пояснения к workflow:**

- jobs `api-tests` и `ui-tests` не зависят друг от друга и идут параллельно (суммарное время — как у самого долгого job);
- `echo "API_PID=$!" >> "$GITHUB_ENV"` — сохраняет PID процесса API в переменную окружения шага, работающую во всех последующих шагах;
- `kill "$API_PID" || true` — остановка API даже при упавших тестах; `|| true` защищает от ошибки «процесс уже завершён»;
- `HEADLESS: 'true'` — переменная окружения тестового процесса; `'true'` в кавычках, чтобы YAML не превратил значение в булево.

### **Критерии оценки**

*   **5 (Отлично):**
    *   Оба job выполняются на GitHub и видны во вкладке Actions.
    *   API поднимается в CI, тесты дожидаются готовности, сервер останавливается после прогона.
    *   UI-тесты работают в headless-режиме; скриншоты падений публикуются и содержательны.
    *   Разобран случай падения UI-теста (TRX + скриншот).
    *   Скриншоты в `images`, работа закоммичена и запушена.

*   **4 (Хорошо):**
    *   Оба job работают, но скриншоты при падении не настроены.
    *   Ожидание готовности API реализовано без цикла (единичная пауза `sleep`), что менее надёжно.

*   **3 (Удовлетворительно):**
    *   Работает только один из job.
    *   UI-тесты падают в CI из-за отсутствия headless-режима.

*   **2 (Неудовлетворительно):**
    *   Workflow не запускается или оба job падают; исправления не внесены.
