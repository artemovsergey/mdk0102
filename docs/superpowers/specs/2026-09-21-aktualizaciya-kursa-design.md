## 1. Контекст

Репозиторий `mdk0102` — методические материалы по МДК 01.02 «Поддержка и тестирование
программных модулей» для специальности 09.02.07 (ИП). Разделы 1–7 наполнены
(лекции 1–22, практики 1–26, СР 1–2), Разделы 8–9 — 10 пустых файлов (0 байт).
Материалы частично устарели: примеры на `net8.0` (снят с поддержки), настройка
окружения под Visual Studio, драйверы браузеров подключаются как NuGet-пакеты
(`Selenium.WebDriver.ChromeDriver`/`GeckoDriver` — устаревший подход), в RestSharp
показан удалённый конструктор `new RestClient(url)`. В КТП фигурируют TestContainers
(требует Docker), log4net и Allure/Jenkins, которых в аудиториях нет.
`Экзамен.md` содержит 20 задач в Python-стиле, не соответствующих C#-курсу.

Ограничения среды: Docker в колледже недоступен; Visual Studio не используется
(аудитории — VS Code / терминал); .NET 10 официально поддерживается только
Visual Studio 2026 v18.0+, поэтому материалы ориентированы на VS Code + C# Dev Kit.
Группы, даты и ссылки на внутреннюю систему — вне публичного репозитория.

## 6. Содержание новых материалов

Формат — по существующим шаблонам: лекция (план → подробное рассмотрение → резюме →
контрольные вопросы), практика (тема, цель, теория, ход работы, практический пример,
варианты заданий, критерии оценки, контрольные вопросы, требования к репозиторию и README),
СР (тема, цель, ход работы, критерии, контрольные вопросы).

### Раздел 8

**Лекция 23** — пирамида тестирования и место интеграционных тестов; что такое
интеграционный тест (реальные зависимости: БД, файлы, HTTP); подходы к тестовой БД
(in-memory провайдер, SQLite, реальная СУБД, обзор TestContainers и почему без Docker);
SQLite in-memory: `DataSource=:memory:`, удержание открытого соединения, общий кэш,
`EnsureCreated`; изоляция данных между тестами; `UseSqlite` в EF Core 10; правила
выбора между юнит- и интеграционными тестами.

**Практика 27** — учебный мини-сервис «Библиотека книг» (`Book`, `LibraryDbContext`,
`LibraryService` с бизнес-правилами). Тестовый проект xUnit + `Microsoft.EntityFrameworkCore.Sqlite 10.0.12`.
Тесты: добавление и выборка книг, уникальность ISBN, запрет удаления выданной книги.
Фикстура/`IDisposable` для соединения SQLite, `EnsureCreated`. Варианты заданий
(журнал студентов, склад, бронирование). README с инструкцией запуска.

**Лекция 24** — цели и метрики нагрузочного тестирования (RPS, время отклика,
p90/p95/p99, доля ошибок); виды тестов: smoke, load, stress, spike, soak; обзор
инструментов (k6, JMeter, NBomber, Locust); k6: виртуальные пользователи, итерации,
`options`, `thresholds`, `checks`, `sleep`; установка на Windows (winget/choco/portable ZIP);
чтение результатов и анализ.

**Практика 28** — учебный SUT: minimal API «Книги» (`dotnet run`, Swagger);
k6-скрипт: smoke `GET /api/books`, сценарий с `POST`, нагрузочный профиль
(ramp-up до N VU), пороги `http_req_duration p(95)<500`, `checks rate>0.95`;
запуск `k6 run`, разбор вывода. Варианты заданий по интенсивности/порогам.
README с инструкцией.

### Раздел 9

**Лекция 25** — зачем логировать тесты (диагностика падений, особенно в CI); уровни
и structured logging; обзор библиотек (встроенный `ILogger`, log4net, NLog, Serilog —
почему Serilog); конфигурация Serilog (`LoggerConfiguration`, консольный и файловый
sinks, шаблоны, уровни); интеграция в тесты через `ITestOutputHelper`; Serilog в
ASP.NET Core; рекомендации (не логировать секреты, уровень в CI).

**Лекция 26** (новая) — понятие непрерывной интеграции; GitHub Actions: workflow,
events/triggers, jobs, steps, runners, матрицы, кэш, артефакты, секреты, бейджи;
YAML-синтаксис; сравнение с Jenkins/GitLab CI (обзорно); Allure — обзорно.

**Практика 29** — подключение Serilog к тестовому проекту (из практики 27);
`ITestOutputHelper` + Serilog-sink для вывода логов в окно теста; логирование
`LibraryService` через `Microsoft.Extensions.Logging` + Serilog; проверка
`dotnet test` с логами; варианты (файловый sink, смена уровня).

**Практика 30** — отчёты: `dotnet test --logger "trx;LogFileName=..."`, структура TRX;
покрытие (`coverlet.collector`, `--collect:"XPlat Code Coverage"`); ReportGenerator
(`dotnet tool install -g dotnet-reportgenerator-globaltool`, HTML-отчёт);
артефакты GitHub Actions (`upload-artifact`); критерии и варианты.

**Практика 31** — подключение проекта к GitHub; workflow `.github/workflows/tests.yml`:
`on: push/pull_request`, job на `ubuntu-latest`, шаги `checkout`, `setup-dotnet`,
`restore`, `build`, `test --logger trx`; выгрузка TRX артефактом; чтение логов и
summary; бейдж статуса в README. Варианты (другая ветка-триггер, фильтры путей).

**Практика 32** — второй job: API-тесты (RestSharp, локально поднимаем SUT) и UI-тесты
Selenium headless Chrome в CI (`ChromeOptions` headless, скриншот при падении);
артефакты при провале; матрица ОС или раздельные jobs. Варианты.

**Практика 33** — кэширование NuGet (`setup-dotnet` с `cache: true` или `actions/cache`),
конкурентность/таймауты, сводные отчёты, retention артефактов, бейдж в README,
сравнение времени сборки с кэшем и без; чек-лист «production-ready» pipeline.

**СР 3** — индивидуальный набор автотестов: юнит-тесты, интеграционные (SQLite),
API-тесты; логирование Serilog; запуск через TRX; workflow GitHub Actions с бейджем;
README. Критерии оценки и варианты предметной области.
